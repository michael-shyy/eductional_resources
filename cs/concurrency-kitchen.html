ORDER #01 · 并发入门

开一家餐厅，
学会多进程、多线程和异步

电脑同时做好几件事，Python 里有三种办法：多进程、多线程、异步。这页用一家餐厅讲清楚它们：谁是厨房，谁是厨师，为什么厨师多了反而会出错，一个厨师怎么同时盯几口锅，以及到底该选哪个。

15 分钟上菜
第一道 · 核心比喻必读

进程是厨房，线程是厨师

进程是一间独立的厨房。它有自己的冰箱（内存）、自己的灶台和食材（文件、网络连接）。两间厨房互相看不到对方冰箱里有什么。

线程是厨房里干活的厨师。一间厨房至少有一个厨师。同一间厨房的厨师共用一个冰箱，谁都能伸手拿东西。

厨房 A（进程 1）
冰箱：鸡蛋 × 12，牛肉 × 3
厨师 1厨师 2厨师 3
厨房 B（进程 2）
冰箱：鸡蛋 × 12，牛肉 × 3
厨师 1

两个冰箱内容一样，但是是两份。厨房 A 拿走一个鸡蛋，厨房 B 不受影响。

这一个比喻能推出几乎所有区别：

开一间新厨房很贵（要装修、买冰箱），所以创建进程开销大。多招一个厨师很便宜，所以创建线程开销小。

一间厨房着火，隔壁厨房照常营业，所以进程互相隔离，更安全。一个厨师打翻油锅，整间厨房都完了，所以一个线程崩溃会带走整个进程。

厨师之间喊一声就能交接，所以线程通信简单。厨房之间要派服务员跑腿传菜，所以进程通信要靠管道、队列、共享内存。

第三道 · 动手试试互动

两个厨师，一块白板

线程共享内存，好处是方便，坏处是会抢。来看一个具体场景。

后厨墙上有一块白板，写着“今天出了几道菜”。这块白板就是一个共享变量。两个厨师（两个线程）每做好一道菜，都要去白板上把数字加 1。

问题在于，“加 1”不是一个动作，而是三个动作：

① 看：抬头看白板上的数，记在心里。
② 算：做好菜，心里算出“这个数 + 1”。
③ 写：擦掉白板，写上心里算好的新数。

如果厨师 1 刚看完，还没写回去，厨师 2 也来看了，两人心里记的是同一个旧数。后面两人各自写回“旧数 + 1”，第二个人写的就把第一个人的盖掉了。明明出了两道菜，白板只加了 1。菜没少，少的是记录。这就叫竞态条件，Python 里的 count += 1 就有这个问题。

锁（Lock）就像白板旁边挂的一把钥匙。谁拿到钥匙，谁才能走完“看、算、写”三步，写完再把钥匙挂回去。另一个厨师只能等。这样三步就变成一个不可打断的整体，代价是要排队，速度会慢一些。

第四道 · Python 特色菜重点

GIL：整间厨房只有一把锅铲

CPython 有一把全局解释器锁，叫 GIL。你可以把它想成：一间厨房无论有多少厨师，只有一把锅铲。谁拿着锅铲，谁才能炒菜（执行 Python 字节码）。

所以炒菜（纯计算）的时候，开 4 个线程也只能一个一个轮流炒，几乎没有提速。但如果厨师在等水烧开（等网络、等磁盘），他会把锅铲放下，别人就能接着炒。所以等待多的任务，多线程依然很有用。

多进程是开 4 间厨房，每间都有自己的锅铲，可以真正同时炒。

拿着锅铲在算 等水烧开（IO）

补充：NumPy、Pandas 的很多底层运算在 C 里执行时会释放 GIL，所以多线程跑大块向量运算有时也能提速。另外 Python 3.13 起有实验性的无 GIL 版本，但目前主流环境仍然有 GIL。

第五道 · 第三种做法新增

异步：一个厨师盯三口锅

想象一个很会安排的厨师。他把汤放上灶，不站着等，转身去切菜；切到一半，蒸锅的计时器响了，他去开锅；然后回来继续切。整个过程只有一个人，但三道菜同时在推进。

这就是异步。在 Python 里，用 async def 定义的函数叫协程，相当于一道菜。await 就是厨师说“这里要等一会，我先去忙别的”。负责安排厨师在各口锅之间跑来跑去的，叫事件循环。

和多线程最大的区别：多线程是操作系统随时把厨师拽走，可能拽在三步操作中间，所以要加锁。异步是厨师自己决定只在 await 时离开，所以中间不会被打断，基本不需要锁。

一个前提

锅必须是“会自己响”的。也就是说，等待的那一步要用支持异步的库，比如 aiohttp、asyncio.sleep。如果你在协程里写了 time.sleep 或 requests.get，厨师就会傻站在锅前，其他锅全部停摆。

不能算

异步只有一个线程，对纯计算没有任何帮助。在协程里跑一段很重的 NumPy 计算，整个事件循环都会卡住。

会传染

只要调用了 async 函数，调用它的函数通常也得变成 async。所以异步更适合从一开始就这样设计的程序，比如爬虫、接收实时行情、网络服务。

第六道 · 多进程的几种写法工具箱

Python 里开厨房的几种方式

多进程不止一种写法。它们底层都是开新进程，区别在于用起来顺不顺手。从推荐程度排：

写法一句话什么时候用
ProcessPoolExecutor请一个厨房经理，你只管下单，他分配厨房首选。接口和线程池一样，换一个词就能在线程和进程之间切换
multiprocessing.Pool老牌厨房经理，功能更多需要 imap_unordered、starmap 这类花样时
multiprocessing.Process自己一间间开厨房，自己管进程数量很少，每个进程干的活不一样，比如一个收数据一个写库
Queue / Pipe厨房之间的传菜口进程之间要持续传消息，比如生产者和消费者
shared_memory / Manager几间厨房共用一个大冷库大数组不想每个进程都复制一份
joblib.Parallel第三方的便捷经理scikit-learn 生态，写一行就能并行一个循环

线程这边对应的是 ThreadPoolExecutor（首选）和 threading.Thread（手动管理）。

第七道 · 点菜指南决策

到底选哪个

选多进程

  • 任务主要在算：因子计算、回测、蒙特卡洛
  • 任务之间互相独立，比如按股票或按日期拆开
  • 希望一个任务崩了不影响其他

选多线程

  • 任务主要在等：下载行情、调接口、读很多小文件
  • 需要频繁共享同一份数据
  • 要用的库是普通阻塞库，比如 requests

选异步

  • 要同时发成百上千个网络请求
  • 长时间挂着接收实时行情、WebSocket
  • 用到的库有异步版本

先别急着并发

  • 能向量化的先用 NumPy 向量化
  • 任务很小，开进程的开销比任务本身还大
  • 瓶颈在磁盘或数据库，加人也没用

一句话口诀：算得多开厨房，等得多招厨师，等得特别多就让一个厨师盯多口锅。

第八道 · 菜谱代码

ProcessPoolExecutor 常用写法

ProcessPoolExecutor 就是厨房经理：你下单，他把单分给几间厨房。下面是最常用的几个函数，每段代码都能直接运行。把 ProcessPoolExecutor 换成 ThreadPoolExecutor，用法完全一样。

函数比喻什么时候用
ex.map(fn, items)一次下一摞单，按单号顺序出菜最常见。一堆输入，函数相同，要结果顺序和输入一致
ex.submit(fn, *args)单独下一张单，拿回一张取餐小票每个任务参数不同，或者想单独查看某个任务
fut.result(timeout)凭小票取餐，没做好就站着等拿结果，子进程的异常也会在这里抛出
as_completed(futs)谁先做好先端谁任务耗时差别大，想边做边处理或显示进度
wait(futs, return_when)等一批单，到条件就停下只要第一份结果，或者最多等几秒
initializer厨房开张前先备料每个进程只读一次大表或模型，不要每个任务都传
add_done_callback菜做好时自动按铃做完后自动记日志、更新进度
shutdown(cancel_futures)打烊，没开始的单不做了出错时提前收工
 
# map：最常用。按输入顺序返回结果，像按单号出菜
from concurrent.futures import ProcessPoolExecutor
import numpy as np

def calc_factor(code):
    x = np.random.default_rng(int(code[:6])).standard_normal(1_000_000).cumsum()
    return x.std()

if __name__ == "__main__":
    codes = [f"{i:06d}.SZ" for i in range(1, 41)]
    with ProcessPoolExecutor(max_workers=8) as ex:
        # chunksize：一次给每个厨房派 4 张单，减少来回传菜的开销
        values = list(ex.map(calc_factor, codes, chunksize=4))
    for c, v in list(zip(codes, values))[:3]:
        print(c, round(v, 2))

    # 多个参数：传多个可迭代对象，按位置一一配对
    with ProcessPoolExecutor() as ex:
        print(list(ex.map(pow, [2, 3, 4], [10, 2, 3])))   # [1024, 9, 64]
# submit：单独下一张单，马上拿到一张取餐小票（Future）
from concurrent.futures import ProcessPoolExecutor
import time

def backtest(name, window):
    time.sleep(1)                          # 假装在跑回测
    return f"{name} window={window} sharpe={window / 10:.2f}"

if __name__ == "__main__":
    with ProcessPoolExecutor(max_workers=4) as ex:
        fut = ex.submit(backtest, "momentum", window=20)   # 可以传关键字参数
        print(fut.done())                  # False：还在做
        print(fut.result())                # 阻塞等待，直到拿到结果
        print(fut.done())                  # True

        # 一次下很多单，用字典记住每张小票对应哪个参数
        futs = {ex.submit(backtest, "reversal", w): w for w in (5, 10, 20, 60)}
        for f, w in futs.items():
            print(w, "->", f.result(timeout=10))   # 最多等 10 秒，超时抛 TimeoutError
# as_completed：谁先做好先端谁，不按下单顺序
from concurrent.futures import ProcessPoolExecutor, as_completed
import random, time

def load_day(day):
    time.sleep(random.uniform(0.2, 1.5))   # 每天的数据量不同，耗时不同
    return day, random.randint(1000, 5000)

if __name__ == "__main__":
    days = [f"2026-10-{d:02d}" for d in range(1, 11)]
    with ProcessPoolExecutor(max_workers=4) as ex:
        futs = [ex.submit(load_day, d) for d in days]
        for i, f in enumerate(as_completed(futs), 1):
            day, rows = f.result()
            print(f"[{i}/{len(days)}] {day} 完成，{rows} 行")   # 适合配进度条
# wait：等一批单，可以选“全部做完”、“第一份做完”或“第一个出错”
from concurrent.futures import (ProcessPoolExecutor, wait,
                                ALL_COMPLETED, FIRST_COMPLETED, FIRST_EXCEPTION)
import time

def cook(sec):
    time.sleep(sec)
    return sec

if __name__ == "__main__":
    with ProcessPoolExecutor() as ex:
        futs = [ex.submit(cook, s) for s in (3, 1, 2)]

        done, not_done = wait(futs, return_when=FIRST_COMPLETED)
        print("最先做好：", [f.result() for f in done])        # [1]

        done, not_done = wait(futs, timeout=1.5)               # 最多等 1.5 秒
        print("1.5 秒内做好", len(done), "份，还剩", len(not_done), "份")

        done, _ = wait(futs, return_when=ALL_COMPLETED)        # 默认就是这个
        print("全部完成：", sorted(f.result() for f in done))
# initializer：每间厨房开张时先做一次准备，比如把大表读进内存
from concurrent.futures import ProcessPoolExecutor
import os

_table = None                              # 每个子进程各有一份

def init_worker(path):
    global _table
    _table = {"000001.SZ": 1.2, "600000.SH": 0.8}   # 实际可以 pd.read_parquet(path)
    print(f"进程 {os.getpid()} 准备好了，读入 {path}")

def lookup(code):
    return code, _table.get(code), os.getpid()

if __name__ == "__main__":
    codes = ["000001.SZ", "600000.SH"] * 4
    with ProcessPoolExecutor(max_workers=2,
                             initializer=init_worker,
                             initargs=("factors.parquet",)) as ex:
        for r in ex.map(lookup, codes):
            print(r)
    # 好处：大表每个进程只读一次，而不是每个任务都重新传一遍
# 异常、回调、取消：后厨出事了怎么办
from concurrent.futures import ProcessPoolExecutor, as_completed
import multiprocessing as mp

def risky(x):
    if x == 3:
        raise ValueError(f"第 {x} 道菜烧糊了")
    return x * 10

def on_done(fut):                           # 回调在主进程里执行
    if fut.exception() is None:
        print("回调：做好了", fut.result())

if __name__ == "__main__":
    ctx = mp.get_context("spawn")           # 明确指定启动方式，Mac 和 Linux 行为一致
    with ProcessPoolExecutor(max_workers=2, mp_context=ctx) as ex:
        futs = []
        for x in range(6):
            f = ex.submit(risky, x)
            f.add_done_callback(on_done)
            futs.append(f)

        for f in as_completed(futs):
            try:
                f.result()                  # 子进程里的异常会在这里重新抛出
            except ValueError as e:
                print("捕获到：", e)

    # 不用 with 时要自己关：cancel_futures=True 会丢掉还没开始的单（Python 3.9+）
    ex = ProcessPoolExecutor(max_workers=2)
    futs = [ex.submit(risky, x) for x in range(100)]
    ex.shutdown(wait=True, cancel_futures=True)
    print("被取消的单：", sum(f.cancelled() for f in futs))
import asyncio, time

async def download(day):
    await asyncio.sleep(1)            # 换成 aiohttp 请求也一样；await 处让出厨师
    return f"{day} done"

async def main():
    days = [f"2026-10-{d:02d}" for d in range(1, 31)]
    sem = asyncio.Semaphore(10)         # 最多同时 10 口锅，防止把接口打爆
    async def limited(d):
        async with sem:
            return await download(d)
    return await asyncio.gather(*(limited(d) for d in days))

t0 = time.time()
print(asyncio.run(main()))              # 启动事件循环
print(f"耗时 {time.time()-t0:.1f}s")    # 30 个任务、每次 10 个，约 3 秒
# 注意：在 Jupyter 里已经有事件循环，直接写 await main() 即可
import threading

eggs = 0
lock = threading.Lock()

def put_eggs(n):
    global eggs
    for _ in range(n):
        with lock:                     # 拿钥匙，做完自动还
            eggs += 1

ts = [threading.Thread(target=put_eggs, args=(100_000,)) for _ in range(4)]
for t in ts: t.start()
for t in ts: t.join()               # 等所有厨师下班
print(eggs)                           # 一定是 400000
第九道 · 后厨事故簿避坑

常见的坑

死锁

厨师 1 拿着盐等酱油，厨师 2 拿着酱油等盐，两人永远等下去。解决办法：所有人按同一个顺序拿锁，或者尽量只用一把锁。

忘写 main

在 Mac 和 Windows 上，子进程会重新导入你的脚本。不加 if __name__ == "__main__":，就会无限开厨房，直接报错。

传不过去

进程之间传数据要先 pickle 打包。lambda、打开的文件句柄、数据库连接都打包不了。传大 DataFrame 也很慢，最好让子进程自己按路径读文件。

改了没用

子进程里修改全局变量，主进程看不到。因为改的是自己厨房冰箱里的那一份。想拿结果，用返回值或 Queue。

开太多

进程数超过 CPU 核数，大家抢核心，反而更慢。计算任务一般设成核数，比如 os.cpu_count()。

嵌套并行

NumPy 底层的 BLAS 自己也会开多线程。8 个进程各开 8 个线程就是 64 个，服务器会卡住。可以设置 OMP_NUM_THREADS=1。
